# NISAR GCOV → GeoTIFF: MAAP DPS (November 18, 2026)

**A standalone repository.** This package contains the user's `NISAR_GCOV_TO_TIFF.py` and `NISAR_GCOV_TIFF.sh` **verbatim**, plus a MAAP-specific wrapper. It does not update or depend on the previous `NISAR_GCOV_Processing` repository.

## Processing

One **NISAR L2 GCOV** `.h5`/`.hdf5` granule is downloaded per MAAP DPS job. The wrapper scans `frequencyA` and `frequencyB`, runs each **complete** HH/HV, VV/VH or RH/RV diagonal intensity pair supported by the new processor, and writes GeoTIFFs to `output/<frequency>/<pair>/`.

Important behavior:

- **FULL FRAME:** The supplied bounding box is an *intersection/eligibility* test. If a granule overlaps the AOI at all, the **entire scene is processed**, including pixels outside the AOI. `--bbox` is deliberately **not** passed to the scientific processor.
- **Product maturity:** CRID `< 5030` uses the provisional `uint8` exception-mask rule; CRID `>= 5030` uses the validated `uint16` anomaly plus polarization-validity-bit rule. Inconsistent stored dtypes trigger warnings and a data-layout fallback in the original processor.
- **Log caveat:** The original processor has a generic status line describing the exception mask as excluding nonzero values. For validated products that status line is imprecise; the detailed per-frame log and actual code correctly use the nonzero polarization-validity bits.
- **Frequency B provisional:** The exception mask uses the processor's 8×8 frequency-A-to-B reduction when applicable.
- **Baseline MAAP settings:** `gamma0` linear power, 7×7 native-grid Enhanced Lee filter, 90% coverage, exception mask ON, EASE2 100 m class M0p1 grid, incidence/LIA ON, no multi-frame mosaic. The original standalone shell launcher still defaults to no speckle filtering.
- **Not a decibel output:** SAR TIFF pixels are in linear power. Quicklooks use dB for visualization.
- **No background launch:** Unlike the standalone launcher, MAAP calls Python directly. A nonzero processor status fails the DPS job.
- **No silent single-pol conversion:** The uploaded processor supports complete co/cross pairs only. Unpaired channels are reported and skipped; a granule with no supported pair fails rather than being marked successfully processed.
- **Never overwrite:** The underlying processor skips existing outputs. The wrapper additionally verifies that expected SAR and geometry files were actually produced.

## Publish to a NEW GitHub repository

Create an empty **public** GitHub repository named `NISAR_GCOV_TIFF_MAAP` under your account, with **no autogenerated README or license**. Unzip this package and run from the extracted `NISAR_GCOV_TIFF_MAAP` directory:

```bash
git init -b main
git add .
git commit -m "Add NISAR GCOV provisional/validated MAAP DPS processor"
git remote add origin https://github.com/preet0lal/NISAR_GCOV_TIFF_MAAP.git
git push -u origin main
```

The new GitHub repo URL only becomes valid **after you create it**. This package does not modify or replace the old GitHub repository.

## Register in NASA MAAP

Choose a suitable GDAL/Pangeo-based MAAP container. MAAP DPS builds from **public Git repos** using the named Build and Run Commands. When registering, give this algorithm **a different name** from your existing GCOV algorithm to avoid replacing it.

| Registration field | Value |
| --- | --- |
| Repository URL | `https://github.com/preet0lal/NISAR_GCOV_TIFF_MAAP.git` |
| Branch/version | `main` |
| Algorithm name | `nisar-gcov-tiff-validated` (unique) |
| Build Command | `NISAR_GCOV_TIFF_MAAP/build_env.sh` |
| Run Command | `NISAR_GCOV_TIFF_MAAP/run_nisar_dps.sh` |
| Suggested starting resource | A sufficiently large memory/CPU worker for full-frame GCOV + 30 m DEM LIA; size from a pilot job before batching |

**MAAP input registration (five positional arguments, in order):**

1. `s3_url` — full `s3://...NISAR...GCOV....h5` granule URI
2. `bbox_w` — AOI west longitude
3. `bbox_s` — AOI south latitude
4. `bbox_e` — AOI east longitude
5. `bbox_n` — AOI north latitude

The run script supports **both** the five positional values and the named form `--s3_url ... --bbox W S E N`, for MAAP installations that use named inputs instead. The bounding box is **NOT used for clipping**.

**The new GitHub repo must be registered and built as a new MAAP algorithm.** Pushing code does not automatically update or launch a MAAP DPS container. A real MAAP test with credentials and one GCOV granule is required before regional/global processing.

## Environment overrides for DPS

`run_nisar_dps.sh` exposes these optional environment variables: `NISAR_GRID_MODE` (`EASE2`/`UTM`), `NISAR_TARGET_EPSG` (`auto`), `NISAR_FREQUENCY` (`all`/`frequencyA`/`frequencyB`), `NISAR_POL_PAIR` (`all`/`HH_HV`/`VV_VH`/`RH_RV`), `NISAR_NORMALIZATION` (`gamma0`/`sigma0`), `NISAR_FILTER` (`enhanced_lee`/`none`/`gamma_map`), `NISAR_FILTER_WINDOW` (`7`), `NISAR_LIA` (`yes`/`no`), `NISAR_MIN_COVERAGE` (`0.90`), `NISAR_USE_EXCEPTION_MASK` (`yes`/`no`), and `NISAR_TILE_WORKERS` (`4`).

Example: For a no-filter, no-LIA test set `NISAR_FILTER=none NISAR_LIA=no` in the DPS environment. For direct local invocation use:

```bash
python nisar_dps_wrapper.py \
  --local_h5 /path/to/NISAR_L2_PR_GCOV_....h5 \
  --bbox 112 -44 154 -10 \
  --grid_mode EASE2 --filter none --lia no \
  --output_dir ./output
```

For normal local/HPC processing of **many** `.h5` files, use the original `NISAR_GCOV_TIFF.sh` instead, which has its own `--mosaic` and `--mosaic_across_modes` options and a `nohup` launcher. Do not register that standalone shell script as the MAAP Run Command.

## Expected outputs

```text
output/
  maap_summary.json
  frequencyA/
    HH_HV/
      NISAR_L_GCOV_..._P05036_100m_enhanced_lee_w7_HHHH.tif
      NISAR_L_GCOV_..._P05036_100m_enhanced_lee_w7_HVHV.tif
      NISAR_L_GCOV_..._P05036_100m_enhanced_lee_w7_frame_count.tif
      NISAR_L_GCOV_..._P05036_100m_enhanced_lee_w7_incidence_angle_deg.tif
      NISAR_L_GCOV_..._P05036_100m_enhanced_lee_w7_local_incidence_angle_deg.tif
      NISAR_L_GCOV_..._P05036_100m_enhanced_lee_w7_EASE2_grid.mat
      NISAR_L_GCOV_..._P05036_100m_enhanced_lee_w7_quicklook.png
      processing.log
      logs/...
```

The output filenames retain the CRID to distinguish provisional and validated products. The wrapper verifies all required TIFF/MAT outputs and produces a compact `maap_summary.json` manifest. Inputs and per-job temporary DEMs are cleaned up after completion.

## Offline testing

```bash
python -m py_compile NISAR_GCOV_TO_TIFF.py nisar_dps_wrapper.py proj_setup.py
bash -n NISAR_GCOV_TIFF.sh run_nisar_dps.sh build_env.sh
python -m unittest discover -s tests -v
```

Offline tests exercise both exception-mask layouts and the full-frame boundary behavior on synthetic GCOV files. They do **not** prove MAAP credential access, remote DEM availability, processing throughput, or container registration.
